# HajiMink 桌面开发说明

## 当前范围

桌面开发版使用 Electron 窗口和独立浏览器视图打开现有 React 工作台。连接名称、地址和选择状态保存在用户数据目录，不同连接使用隔离的临时浏览器会话。应用退出后临时浏览器数据会清除，设备凭据在系统保护的存储可用时可跨重启恢复。删除连接不会删除远程项目和会话。远程地址使用 HTTPS，HTTP 仅允许本机环回地址。

Windows 默认提供 `http://127.0.0.1:3000` 本机连接。全新用户资料首次打开时会进入网关引导，等待用户选择端口并启动；旧资料保留原来的启动行为。本机 `local` 模式依靠本机环回限制，不适合通过 Tunnel 发布。端口已被占用时，界面显示冲突，不自动连接或结束占用进程。网关页可将端口改为 1024 至 65535 之间的整数；修改运行中的网关需要确认短暂重启。启动失败时，程序只在确认实例已退出后尝试恢复原端口，无法确认时会保留现场并提示检查。可以通过连接管理显式添加已有网关地址。

macOS 和 Linux 当前只提供远程客户端入口，本机 Agent 接入尚未支持。首次使用需要添加远程连接，跨平台构建与真实远程联调尚待验证。

### 接入已有的远程网关

在“设置 → 连接”选择“添加连接”，选择 NATAPP、SakuraFrp、Tailscale、Cloudflare Tunnel、自建服务器或其他已配置地址。设置内文档提供服务商指南。网关页提供服务商选择、访问地址、登录保护和连接检查；自建服务器的输入方式不会自动配置中转。选择服务商只记录连接类型，不会替用户注册账号或创建隧道。Windows 的 NATAPP 客户端可在用户选择文件后交给 HajiMink 管理；其他服务商客户端仍由用户自行管理。

填写已经提供 HajiMink 网关服务的服务器 IP、域名或 HTTPS 地址。省略协议时，桌面端使用 HTTPS；可以填写端口，例如 `203.0.113.10:8443`。中转服务器的 IP 需要先配置实际隧道和 HTTPS 网关，单个 IP 无法自动创建转发。远程连接必须验证有效的 HTTPS 证书，IP 地址访问同样需要证书覆盖该地址。本机 HTTP 仍只允许 `localhost` 和 `127.0.0.1`。

“测试连接”只向该地址的 `/api/auth/bootstrap` 发送一次不含登录凭据的请求，限制等待时间和响应大小，不跟随跳转。它区分已识别的网关登录接口、额外认证或跳转、非网关响应和无法连接。识别接口不等于验证服务器身份，也不代表已登录或测试通过全部功能；请核对服务器地址后再进行设备授权。

网关页的“检测连接”不发送登录凭据，也不跟随跳转。未保存地址只检查入口响应，不能证明它属于本机网关或已受到保护。已保存且由本机接管的独立登录地址还会检查未登录业务接口、比对本机与远程登录响应，并尝试一次受限的 WebSocket 双向诊断。服务商阻断 WebSocket 或移除诊断请求头时可能显示未通过。临时响应可以被中转方转发或伪造，因此检查不能证明服务器归属、其他路径、持续连接或真实设备登录。

“设置 → 日志”显示远程入口最近一次检查的详细结果和时间。服务商、网关实例、端口、访问地址或登录设置发生变化后，旧结果会清除。这个状态不是隧道客户端的实时运行状态，服务商客户端仍由使用者自行管理。

访问地址输入框接受域名、服务器 IP 或 HTTPS 地址，省略协议时默认 HTTPS。窗口中的未保存修改会在焦点或状态变化时保留，并可恢复为已保存地址。退出桌面应用后草稿不会保存。检测未保存地址不会改变已保存地址的检查结果；日志页显示已保存地址，方便区分检查对象。

新版工作台与新版网关会在实时连接上交换一次不含对话内容的双向检查，确认连接能收发后才显示实时同步正常。运行期间，如果一次检查没有得到回应，工作台会提示重新连接并暂时禁用会话操作；草稿保留，不会自动重发。正常计时下检查间隔为 20 秒，等待回应 10 秒；浏览器后台限制或设备休眠可能延后检测。旧网关没有这一检查能力，继续沿用原有连接判断。新版网关还会回收长时间没有回应的实时连接，不会结束其他进程或 Codex 任务。此检查不验证服务器身份，也不能代替真实服务商和设备的联调。

连接资料因磁盘或权限问题无法保存时，应用会保留原来的连接和工作台页面，并提示保存失败。请检查用户资料目录是否可写，再重试。

现有版本的连接配置会保留，旧记录默认显示为“其他地址”。每个连接独立保存名称、标准化后的地址和连接方式；服务商账号、密码和隧道令牌不会存入连接列表。Cloudflare Access 等外部认证页面当前仍需使用系统浏览器，桌面设备授权适用于启用设备授权的 `owner` 模式网关。

首次打开网关页后，可以先选择端口并启用网关。需要远程访问时，再选择连接方式、填写 HTTPS 地址并设置密码或通行密钥；仅在本机使用时无需配置远程访问。

服务商只有在隧道客户端启动后才显示访问地址时，可以展开“还没有访问地址？”并选择“先保护网关”。HajiMink 会先把网关切换到受保护状态并锁定工作台，不会把临时占位地址打开给浏览器；然后启动服务商隧道，取得最终 HTTPS 地址，再回到网关页填写并保存。网关尚未设置登录方式时，可以用设置码在最终地址选择密码或通行密钥；IP 地址需要可信证书并使用密码。已有隧道应在进入受保护状态前暂时停止。

桌面默认的 `local` 模式网关只接受本机请求，不能直接通过隧道开放。计划远程访问时，先关闭指向本机模式的已有转发，再选择密码或通行密钥完成独立登录设置。密码方式先在网关页打开账户页面设置密码，填写自己的 HTTPS 地址并启用独立登录。本机模式下保存的密码不会保护本机访问，必须切换到独立登录后再开放远程入口。

通行密钥方式需要填写最终 HTTPS 域名，并在网关页选择首次使用通行密钥。桌面端显示有效 10 分钟的一次性设置码；按服务商教程配置隧道和有效证书后，在最终域名输入设置码，再使用设备的面容、指纹或 PIN 创建通行密钥。设备不支持通行密钥时，也可以在该页面改用密码。设置期间网关显示待设置，工作台内容和实时连接保持锁定。设置码只能兑换一次，失效后可在本机重新生成；新码会使旧码和未完成的设置会话失效。桌面设置码面板会显示已保存的适用地址；网关实例或地址发生变化时，面板会隐藏设置码并提示核对。启动隧道并检查入口后，可以点击“在浏览器打开设置页面”，核对地址并手动输入设置码。应用只打开当前网关实例对应的已保存 HTTPS 地址，不将设置码放进网址；地址草稿不一致、设置码过期或已使用时会提示处理。

网关页支持选择 NATAPP、SakuraFrp、Tailscale、Cloudflare Tunnel 和自建服务器，选择结果保存在本机资料。各服务商的基本配置步骤与官方教程入口位于设置内文档；可用域名、HTTPS、转发类型和服务范围以服务商当前方案为准。

通行密钥与域名绑定，更换域名后可能需要重新添加。桌面版可以修改已启用的访问地址，但不会自动创建隧道或证书。转发需要保留外部域名的 Host；服务商隧道自动开通和真实公网联调尚未实现或验证。NATAPP 客户端可按下文使用受限后台管理。

### Codex CLI 终端

在工作台选择 Codex CLI 并点击启动，即可在终端中使用网关电脑上安装的 CLI。选择项目或项目中的会话时，CLI 使用对应的项目目录；未选项目时使用网关电脑的用户目录。安装和登录需要在网关电脑完成

终端断开或网关停止会结束当前 CLI 进程。远程访问前请启用登录保护和 HTTPS，并确认授权设备的使用者可信

## 网关生命周期与安全

Windows 桌面进程通过独立后台控制器启动和监测本机网关。控制通道采用仅授予当前用户的命名管道访问规则、拒绝远程客户端的创建标志和双向挑战应答；控制凭据使用 Windows DPAPI 加密保存。重新打开桌面时，应用会检查控制器和网关的可执行文件、启动参数、进程创建时间、实例身份及数据目录，再连接已运行的实例。停止请求通过经过验证的控制器发送给它自己启动的子进程，进程无响应时不会按 PID 强制结束。

停止网关时会先通知实时连接关闭，并短暂等待握手和连接退出。尚未发完请求头、且没有正在处理的响应的连接会被关闭；已开始的写操作和响应会继续处理。长时间运行的请求仍可能超过控制器等待时间；此时不会强制终止其他进程。

关闭窗口会收起到托盘，程序和服务继续运行。选择“退出软件”时，若有受管理的本机服务，会先请求确认，再停止 HajiMink 管理的 NATAPP 和网关；CLI 终端断开，Codex 桌面会话中的任务不会主动停止。其他服务商客户端由用户自行管理。未能确认服务身份或停止状态、或无法保存恢复记录时，桌面保持运行并提示检查。

正常退出后，桌面会尝试恢复退出前运行的受管理网关；NATAPP 仅在原文件配置仍可用且安全检查通过时恢复。用户手动停止的服务保持停止。使用网关开关重新启动并成功后恢复正常启动策略。停止未确认时，不会启动替代实例或结束未知进程。

手动停止状态无法保存时，程序仍会尝试停止服务并提示检查资料目录。修复保存问题后，可在日志页选择“保持停止”重试；在保存成功前，重新打开桌面时可能自动启动。控制器意外退出、数据被移动或实例记录损坏时，当前版本会保留记录并提示无法安全接管；确认相关进程状态前不要删除 `controller.instance.json` 或 `gateway.instance.lock`。系统关机、注销和异常断电场景尚未验收。控制器故障自动恢复、Windows 登录自启和网关异常的有限重试仍待实现。

日志页面只显示本次桌面运行期间生成的固定启停事件，不读取或写入网关原始标准输出、错误输出、密码、Token、Cookie 或聊天正文。旧开发版可能已在用户数据目录留下未脱敏的 `gateway.stdout.log` 和 `gateway.stderr.log`，新版本不会自动删除它们，请在分享或清理前自行检查。

Cloudflare Tunnel 可由已有的 `scripts/Start-Tunnel.ps1` 单独管理，桌面版尚未接管该服务。项目另有隔离的 Cloudflare Tunnel 生命周期原型：它检查正式登录模式、使用 Token 文件、读取连接状态，并在核验可执行文件、参数和进程创建时间后通过进程句柄停止测试实例。该原型尚未与桌面控制器、正式网关身份或当前线上 Tunnel 接通；`401` 检查也不能单独证明网关身份或远端路由安全。远程网页没有桌面控制接口，桌面外壳限制跨站请求、跳转、弹窗、下载和权限申请；网页中的外部登录跳转与外部链接会被拦截。

### NATAPP 客户端管理

Windows 网关页选择 NATAPP 后，可以分别选择自己从服务商取得的 `natapp.exe` 和已经配置好的 `.ini` 文件，再保存文件位置。HajiMink 不下载或验证客户端来源，也不读取、复制或修改 `.ini` 内容；文件可能包含服务商令牌，请由所有者自行限制访问并备份。服务商控制台中的隧道、HTTPS 和目标端口仍须由所有者配置，目标应指向当前电脑的 `127.0.0.1` 和网关端口。

只有已确认启用独立登录或受限首次设置的本机网关才能启动 NATAPP。HajiMink 使用所选配置文件启动客户端并关闭客户端日志；如果检测到已有 `natapp.exe` 进程，会提示用户自行管理，不接管或结束该进程。客户端运行只表示进程存在，远程入口仍需手动检查并亲自登录验证。部分 NATAPP 方案提供 HTTPS 可能需要付费，以服务商当前说明为准。HajiMink 不显示客户端窗口；若访问地址只能在客户端窗口查看，请先停止本程序启动的客户端，再自行运行客户端。

收起窗口时受管理的客户端继续运行；正常退出软件时会停止，并在下次启动时根据保存的配置和安全检查尝试恢复。客户端自行退出后，程序只有确认原实例已经结束且系统没有其他 NATAPP 进程时，才会清理该实例记录，允许重新启动；检查失败时会保留记录，提示用户核查。停止网关时先停止由 HajiMink 启动的 NATAPP；身份无法确认时不会结束未知进程。绑定最终地址或重新生成设置码时，已确认的 NATAPP 客户端保持运行；修改本机端口或手动重启网关时客户端会停止，需要更新服务商目标后再次启动。系统登录自启与客户端自动重试尚未实现。真实 NATAPP 服务和公网域名仍需人工验收。

### 远程设备授权

选择 HTTPS 远程连接后，点击“授权设备”。应用向网关申请确认码，并打开该网关的系统浏览器授权页面。使用所有者密码或通行密钥登录后，核对桌面端和浏览器中的确认码，再允许或拒绝。浏览器账户页面可以逐个撤销设备。授权默认有效 8 小时，也可以在确认时选择 7 天。

系统浏览器授权需要网关启用并部署支持该功能的 `owner` 模式。`access` 模式继续通过浏览器访问。桌面主进程保管请求秘密和设备令牌，每个连接使用独立会话。Electron `safeStorage` 可用时加密保存设备令牌；Linux 缺少安全存储后端时只保存在内存，退出应用后需要重新授权。

目前已在 Windows 使用临时 HTTPS 网关和测试账号完成自动联调；真实远程网关、macOS 与 Linux 的系统密钥存储和设备联调仍待验证。

### 后台接管验证边界

自动检查覆盖控制通道权限、错误凭据、伪造服务、请求重放、实际进程路径和启动参数校验，以及隔离数据目录下的桌面退出、重新连接和停止。测试还覆盖中文与空格路径、端口冲突和网关不响应停止请求。其他 Windows 用户、远程 SMB 客户端、全新系统以及长期运行场景仍需验证。

## 开发和检查

在项目目录执行下列命令；网页和网关构建均放在 `.local/hajimink-stage`，避免覆盖运行中的线上 `dist` 与 `dist-server`：

```powershell
npm ci
npm run check
npm test
npm run build:desktop:fixture
npm run test:gateway-manager
npm run test:port-change # 本机端口更改和冲突恢复
npm run test:owner-setup # 密码优先配置和通行密钥登录
npm run test:passkey-setup # 设置码、通行密钥首次设置及密码备用
npm run test:private-control # Windows 私有通道和凭据
npm run test:gateway-intent # 手动停止和自动启动策略
npm run test:desktop:intent # 隔离检查停止状态和桌面操作
npm run test:controller # 独立控制器和进程身份
npm run test:tunnel-manager # 隔离的 Tunnel 生命周期原型
npm run test:desktop:controller # 桌面退出与重新连接
npm run test:desktop
npm run test:device-ui # 测试用 HTTPS 网关、浏览器与 Electron 联调
npm run test:stream-ui # 实时连接故障、恢复和草稿保护
npm run test:workspace-ui # 使用模拟桌面和终端检查桌面及手机工作台
npm run test:desktop:gateway
npx tsx scripts/test-limited-ui.ts # 用模拟适配器检查部分兼容状态的界面
```

`test:gateway-manager` 和 `test:controller` 使用临时端口和数据目录检查进程归属、冲突、并发启停、异常和日志边界。`test:desktop` 使用模拟网关检查桌面连接隔离。`test:device-ui` 使用 OpenSSL 生成临时证书，并在 Windows 使用 Microsoft Edge 与 Electron 进行本机隔离联调。`test:desktop:gateway` 只读连接当前 Codex 项目和会话目录，不发送消息、修改设置或停止任务。`test-limited-ui.ts` 使用模拟适配器，检查保留的部分兼容状态界面，不提交真实 Agent 操作。

Windows x64 打包需要已核对的 Node.js `24.19.0` 可执行文件及 Windows 自带的 .NET Framework 编译器，用于生成本机控制通道辅助程序。运行 `npm run package:desktop:win` 会先在隔离目录安装锁定的生产依赖并校验 Node.js 文件摘要，再构建未签名安装程序和 ZIP；`npm run package:desktop:win:dir` 生成未打包目录。输出默认位于 `output/hajimink-desktop-build`，并生成 `SHA256SUMS.txt`。`npm run test:desktop:packaged` 使用临时目录和端口检查该目录中的应用，`npm run test:desktop:controller` 额外验证桌面退出、重连和从新窗口停止；如测试其他构建，可通过 `HAJIMINK_DESKTOP_BINARY` 指定完整程序路径。

构建成功和自动启动检查不等于发布验收。安装、升级、卸载、长期运行、跨平台构建、许可证复核和真实远程设备联调仍须分别验证。
